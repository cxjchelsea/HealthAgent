# S2-B1 — Unified Conversational Agent 纵向切片

## 范围
基于已完成 S1 会话/历史与 S2-A LangGraph/Tool Calling 进行渐进式接线，不新建平行会话存储。保留 `POST /conversations/{id}/messages`（S1 SSE 对照）和 `POST /agent/runs`（S2-A 单次 Run 对照）。

新增 `POST /conversations/{id}/agent/messages`：请求 `content` 与 `client_request_id`，使用既有会话所属用户检查、Turn 请求 ID 去重、持久化与最近完成消息构造上下文，然后调用原来的 AgentLoop。在同一个窗口中，模型可以直接回复或自主调用工具；成功回复保存进原会话的 messages/turns。

网页默认 Agent 模式，共用一个 conversation id；刷新后恢复原有已存消息，可切回 S1 SSE 模式对照。Agent 本阶段仍返回最终 JSON，执行 Trace 只显示在当前页面中。

## 不夸大范围
- **B1** 仅接通已完成用户/助手消息形成的多轮上下文，不永久存储完整工具 Observation，不支持跨 Run 任务列表延续；B2/B3 再做结构化 Context 与任务状态。
- 不做长期记忆、MCP、医学能力、Agent SSE、服务端真实取消。
- 失败的 Agent 响应为 `provider_error`，不作为后续完成的助手历史；API 返回 503。
- 当前同步 Agent 调用没有完整并发序列化，生产多并发会话需后续增加锁或乐观版本控制。

## 验收
- `python -m pytest -q`：同会话“你好 → 调工具计算 7*6 → 询问刚才结果”、重读历史、重复请求冲突、跨用户 404、提供商失败不写成成功。
- `python -m pytest tests/test_s2a_live_optional.py -q -m live` 仍可测试 S2-A 原生调用。
- 网页 `python -m uvicorn apps.api.main:app --reload`；访问 `http://127.0.0.1:8000/`，默认 Agent 模式进行三轮测试，再刷新检查历史；切换 S1 模式继续验证 SSE。
- 真实 Qwen3:14b 三轮同会话验证尚需用户在 Windows 环境执行；没有真实测试结果前 B1 不标记 CLOSED。
