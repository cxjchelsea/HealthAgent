# S2-B2 — 单一 Agent 主链与有界上下文增强

## 1. 阶段目标与边界

主入口固定为 `POST /conversations/{cid}/agent/messages`，保留 Conversation/Message/Turn 和原有 LangGraph AgentLoop。**移除** `/conversations/{cid}/messages` 的 S1 SSE 路由及 `/agent/runs` 单次 Run 路由，不再提供 UI 模式切换。旧对话数据不删除，原来的只读会话与新建接口继续可用。旧 S1 / S2-A 实现历史可从 Git 查看，本阶段不再运行它们的 HTTP 入口。

## 2. 已实现功能与代码落点

- `agent/context.py`：从已完成的 `user/assistant` 历史记录选择最近的完整消息，按 `max_history_messages` 与 `context_max_chars` 两种上限裁剪。
- `apps/api/main.py`：唯一的会话内 Agent 写入口调用 Context Builder 后复用 `AgentLoop.run(history=...)`，仍按 S2-B1 保存结果和 Turn。
- `apps/web/index.html`：单模式会话 UI；支持对话持久化、恢复、工具执行 Trace 和新建会话。
- `agent/config.py`：`CONTEXT_MAX_CHARS`，默认 24000 字符。**字符预算不是官方 Token 预算**。

## 3. 验收证据与复现方式

```powershell
python -m pytest -q
python -m uvicorn apps.api.main:app --reload
```

核对旧路由分别返回 404 与 405，新路由正常。对同一会话执行“你好 → 计算 7×6 → 刚才结果是什么”；刷新历史应保留。大段历史应被预算裁剪、用户和助手角色不变、失败消息不得进上下文。CI 和真实 Qwen 人工验收完成前，本阶段状态为 **IMPLEMENTED / PENDING LIVE ACCEPTANCE**。

## 4. 当前限制与未完成事项

- 不保存跨 Run 的原始工具 Observation 和任务状态；单轮 Trace 网页显示，刷新只恢复回答。
- 目前按字符串长度做保守预算，不是精确 Token；超过当前预算的历史保持完整边界，不能保证关键旧事实一定被保留。
- 同一 Conversation 并发请求严格序列化、服务端取消、Agent SSE、长期记忆写读和跨会话检索仍待后续开发。
- 保留 S2-A 内部 `AgentLoop.run` 测试（无需旧 HTTP 入口），以保障工具循环回归。

## 5. 后续处理方向

真实 Qwen 主链长对话与预算边界实测后再关闭 B2；随后 B3 在此同一主链上增加会话级任务状态。严禁另建正式 Agent 执行入口。
