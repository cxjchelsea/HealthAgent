# S2-B5 — Context and Memory Evaluation

This stage extends the existing HealthAgent evaluation harness. It does not create a new production Agent route.

## Automated evaluation
Run `python -m evals.s2b5_benchmark`. The suite calls the **real unified conversation HTTP route**, using a deterministic scripted model decision fixture rather than a remote LLM. It validates context budget and historical database retention; memory consent rejection, save, cross-conversation recall, owner isolation, denied overwrite, correction, deletion; task persistence and isolation; request-ID duplicate protection; restart persistence. Results are written to `evals/results/s2b5/offline-v1.json`, containing case IDs, pass/fail, elapsed time and exception type only (not messages or memory contents). `python -m pytest -q` and CI also execute the harness.

**Do not interpret offline scripted pass rates as Qwen accuracy.** The live provider's autonomous tool selection, paraphrase robustness, tool choice, and long-history performance are not captured by a scripted fixture. Char budgets are not model tokenizer budgets.

## Manual live Qwen acceptance
Run the existing web UI with the model provider configured. In the same session: save an authorized memory; open another session for the same user and recall; attempt denied overwrite and verify original; correct and delete via the authenticated management API; test task persistence; send long conversation turns and inspect context-bound effects. Record counts for attempted/successful tool choices, incorrect answers, latency and failures, avoiding raw sensitive messages. This is a separate live-model evidence layer.

## Scope
S2-B5 is evaluation and regression only. It adds no alternative Agent chain, new memory storage, automatic semantic memory extraction, production concurrency handling or streaming support.
