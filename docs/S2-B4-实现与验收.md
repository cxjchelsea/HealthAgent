# S2-B4 controlled long-term memory

Existing conversation Agent route is the sole execution entry. A versioned user_memories table stores user-owned key/value facts. MemoryStore provides read and write operations to the existing AgentLoop through save_memory and recall_memory tools.

Agent-initiated writes require memory_write_consent=true on the current request; the UI exposes a per-turn checkbox. Authenticated GET /memories, PUT /memories/{key}, and DELETE /memories/{key} support review, correction, and deletion. Memory is shared across the same user's conversations, not across users.

Scope: exact-key recall only, no semantic retrieval, extraction queue, source confidence, automatic promotion or background memory process. Live Qwen: user verified consented save, cross-conversation recall, denied update, and reread remaining original value. Additional automated evidence verifies denied write does not mutate storage. Final PR CI and merge review still required. Changes must not be merged until checks and user acceptance complete.
