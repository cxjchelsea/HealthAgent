## 1. 阶段目标与边界

- **S0**：可启动的 API、数据库、环境配置、迁移、测试、最小评测和 CI 基线。
- **S1**：真实模型多轮通用聊天、SSE、历史和失败/取消状态；不将其称作自主工具 Agent。
- 非医学，不引入真实健康资料。与 S2-A 独立的 Agent 工具循环分开验收。

## 2. 已实现功能与代码落点

| 功能 | 代码 / 接口 | 实际能力 |
|---|---|---|
| 配置与提供商 | `agent/config.py`、`agent/providers.py`、`.env.example` | Fake/OpenAI-compatible/Ollama Proxy；超时、历史长度、演示身份等配置 |
| API 就绪与模型 | `GET /healthz`、`/readyz`、`/model` | 进程/数据库探测、模型标识（不包含密钥） |
| 会话与消息 | `POST/GET /conversations`、`GET /conversations/{id}`、`POST /conversations/{id}/messages` | 会话拥有者隔离、去重请求 ID、持久化完成历史 |
| SSE 与网页 | `apps/api/main.py`、`apps/web/index.html` | 增量回复、错误与结束事件、取消浏览器请求、历史恢复 |
| 数据与迁移 | `services/db.py`、`services/migrate.py`、`alembic/` | SQLite 开发、PG 16 CI 迁移检查；现使用 Alembic 而不是旧的 `create_all` 启动路径 |
| 目标理解预备 | `agent/understanding.py`、`POST /understanding` | 保守规则式结构输出，非完整 LLM 目标理解 |
| 测试评测 | `tests/`、`evals/runner.py`、`.github/workflows/ci.yml` | 单元/集成及 5 条离线 Smoke；真实模型用例显式 opt-in |

## 3. 验收证据与复现方式

| 项目 | 已具备证据 | 尚不能声称 |
|---|---|---|
| 开发与回归 | `pytest -q`、`python -m evals.runner`，合并后 main 的 CI 成功 | 全项目 lint/mypy/format 全覆盖 |
| PostgreSQL | CI PostgreSQL 16 服务启动、Alembic 迁移和重复执行检查 | Docker Compose + API/PG 完整现场 E2E |
| Qwen 通用聊天 | 用户于 2026-10-19 报告 Windows Qwen3:14b、多轮、恢复、SSE、停止等现场结果 | 所有项目原定连续五轮/10 条 Token、延迟记录均已有标准化机器证据 |
| 真实模型 opt-in | `$env:RUN_LIVE_MODEL_TEST="1"; python -m pytest tests/test_live_optional.py -q -m live` | 默认 CI 实际调用了真实 Qwen |
| 官方 Token | SSE 明确 `token_usage_available: false` | 输出字符数等同于模型官方 Token |

精确合并基线：S0/S1 PR #1 为 https://github.com/cxjchelsea/HealthAgent/pull/1 （合并提交 `572bffdf44e033585dc1a73858390931ac9c7287`）；S2-A 合并后主分支 `dc253d2433ad7a95a0266ceb6c67622854e33a9a` 的 CI 同时涵盖 S0/S1 回归。
