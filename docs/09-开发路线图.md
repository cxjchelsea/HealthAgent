## 3. S0/S1 已实现的基础能力

- `apps/api/main.py`：`/healthz`、`/readyz`、`/model`、会话创建/历史查询，以及 S2-B 起唯一正式 Agent 消息写入口。S1 SSE 为历史实现，不再开放其旧 HTTP 路由。
- `agent/providers.py`：Fake、OpenAI-compatible、Ollama Proxy；真实 Qwen3:14b 已有用户现场验证。
- `services/db.py` + `services/migrate.py` + `alembic/`：会话、消息、Turn 与迁移；CI PostgreSQL 迁移验证。
- `apps/web/index.html`：统一 Agent 多轮页面、新建/恢复历史、工具 Trace 展示和本轮长期记忆授权勾选；最终 JSON 非流式，停止等待不等于服务端取消。
- `agent/understanding.py`：保守规则式 GoalIntake，**不是**完整的模型驱动意图理解和可靠的歧义澄清。
- `.env.example`、`tests/`、`evals/runner.py`、`.github/workflows/ci.yml`：开发示例、回归测试和有限范围静态门禁。

### S0/S1 未完成或待补证（不随 S2-A 合并自动关闭）

1. `docker compose up --build` 后完整 API + PostgreSQL 读写的可复验证据。
2. 完整依赖锁与全项目 Ruff/mypy/格式门禁；当前 CI 仅覆盖限定静态检查。
3. S1 歧义澄清的端到端模型行为验证；GoalIntake 仅提供基础接口。
4. S1 连续对话、延迟、官方 Token 等原定证据的统一归档；尚未接入供应商官方 Token 用量。
5. 服务端主动取消接口与代理环境一致性测试；前端取消 fetch 不等于服务端取消。

详见 [S0-S1-实现与验收](S0-S1-实现与验收.md)。
