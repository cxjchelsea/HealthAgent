# HealthAgent 开发路线图

日期：2026-10-19。阶段划分以 `06-分阶段实施与验收.md` 为准。本文记录代码里已经落地的能力，以及后面各阶段要做的事。

当前位置：**S0 工程基线可在本机运行，S1 通用对话基础已接到自动化测试。** 下一阶段是 S2，在没有医疗代码的前提下做出可验证的自主执行闭环。S3 及以后才进入健康领域。

## 已经实现的内容

### S0 工程基础

目标是让一个新环境能跑起 API、测试和一个不依赖模型的评测，不回答医学问题。

| 交付 | 落点 | 具体行为 |
|---|---|---|
| 仓库骨架 | `agent/`、`apps/api/`、`apps/web/`、`services/`、`evals/`、`tests/`、`docs/` | 单仓库可编辑安装，包名 `healthagent-s0-s1` |
| 配置 | `agent/config.py`、`.env` | `Settings` 读取数据库、供应商、超时、输出上限、历史条数、输入长度、演示身份。未识别的环境变量被忽略 |
| 进程与就绪检查 | `GET /healthz`、`GET /readyz` | 存活返回 `ok`；数据库执行 `SELECT 1` 失败时返回 503。`readyz` 同时报告 `provider_configured` |
| 数据存储 | `services/db.py` | 启动时 `create_all` 建立 `conversations`、`messages`、`turns`。本地默认 SQLite；`compose.yml` 声明 PostgreSQL 16 |
| 模型双入口 | `agent/providers.py` | `fake` 返回固定中文片段，供测试。`openai_compatible` 走 Chat Completions 流。`ollama_proxy` 走 `/chat` 的 NDJSON。未配置或上游失败抛出 `ModelUnavailable`，不把失败写成成功回复 |
| 日志 | `apps/api/main.py` | 每次生成记录 run、会话、状态、耗时、首个增量延迟、增量次数、输出字符数。供应商失败只记异常类型 |
| 评测基线 | `evals/runner.py`、`evals/datasets/smoke-v1.jsonl` | 5 条样例做去空白和小写比较，写出 `metrics.json` 与 `manifest.json`，`real_model_calls` 为 0 |
| 持续集成 | `.github/workflows/ci.yml` | 推送和 PR 上执行 `pytest`、`python -m evals.runner`、`compileall` |
| 容器入口 | `Dockerfile`、`compose.yml` | 镜像启动 uvicorn；编排文件把 API 指到 PostgreSQL，并带上模型相关环境变量 |
| 测试隔离 | `tests/` | 用例使用临时 SQLite。真实模型用例带 `live` 标记，未设置 `RUN_LIVE_MODEL_TEST=1` 时跳过 |

### S1 通用对话

目标是创建会话、连续对话、流式回复、停止生成和查看历史。这一阶段只称为通用对话基础。

| 交付 | 落点 | 具体行为 |
|---|---|---|
| 会话 API | `POST/GET /conversations`、`GET /conversations/{id}` | 创建会话、列出当前身份的会话、按时间读取消息 |
| 发消息 | `POST /conversations/{id}/messages` | 请求体为 `content` 与至少 8 字符的 `client_request_id`。同一会话重复请求 ID 返回 409。超过 `max_input_chars` 返回 413 |
| 流式事件 | SSE | 依次发出 `started`、`message_delta`、`usage`、`message_done`。供应商异常改为 `error`，`usage` 用输出字符估算，并标明 `token_usage_available: false` |
| 持久化与上下文 | `Message`、`Turn` | 用户消息和助手消息入库。下一轮只把状态为 `completed` 的最近若干条交给模型。`Turn` 记录请求 ID、状态、输入输出字符和耗时 |
| 失败与取消 | `produce()` | 客户端断开后停止继续向上游读取，助手状态写成 `cancelled`。超时或供应商错误写成 `provider_error`，不记为完成历史。半截输出会留下，但状态不是 `completed` |
| 身份隔离 | `USER_TOKENS`、`ALLOW_DEMO_IDENTITY` | Bearer 令牌映射到用户 ID。别人的会话返回 404，未带令牌且关闭演示身份时返回 401。默认演示身份只用于本机 |
| 模型信息 | `GET /model` | 返回当前供应商和模型名，不返回密钥。`ollama_proxy` 可以不配置 `MODEL_API_KEY` |
| Ollama 适配 | `OllamaProxyProvider` | 解析 NDJSON，去掉 `<think>` 推理文本，输出被长度截断时视为失败 |
| 页面 | `apps/web/index.html`，由 `GET /` 返回 | 发送、流式追加、停止（取消当前 fetch）、新建会话、用 localStorage 恢复历史。首个内容片段到达前显示等待状态 |
| 自动化覆盖 | `tests/test_api.py`、`test_closure.py`、`test_ollama_proxy.py`、`test_eval.py` | 覆盖健康检查、隔离、SSE 落库、重复请求、失败不记完成、两轮上下文、页面恢复、中途超时、代理流解析和错误不外泄 |

对应的测试命令：

```bash
pytest -q
python -m evals.runner
```

### 对照 06 仍未关闭的门槛

下面这些写在 S0/S1 验收里，当前代码还没有完成。路线图不把它们算作已通过。

- Compose 拉起后的 API 与 PostgreSQL 联合验证（S0-AC01）。
- 依赖锁、`.env.example`、Alembic 迁移、ruff/mypy 门禁。
- 独立的目标/意图结构提取和歧义澄清（S1-W3、S1-AC04）。现在模型直接看到历史消息。
- 真实供应商连续五轮对话，以及至少 10 条带延迟和 Token 的运行记录（S1-AC01、S1-AC05）。可选用例在 `tests/test_live_optional.py`，默认跳过。
- 服务端主动取消接口。页面停止只取消浏览器请求，断线后的取消一致性还没在代理环境验证。
- 供应商官方 Token 用量。现在的 `usage` 是字符估算。
