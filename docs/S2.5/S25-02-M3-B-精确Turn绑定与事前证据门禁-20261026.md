# S25-02 M3-B exact same-turn evidence gate — 2026-10-26

Status: **isolated comparator implemented; authenticated real pre-turn capture NOT YET WIRED**.

New `evals/s25_02_m3_identity_parity.py` refuses to compare purported
pre-turn decisions unless all of the following are supplied by an external,
trusted capture: nonempty exact conversation/request/Turn identifiers; the
same pre-execution snapshot identity; the same final legacy observation
identity; and `pre_execution_host_snapshot` provenance. It then invokes
the conservative route comparator and never authorizes execution.

This prevents treating M2 `facts_from_legacy_observation` (derived only
after legacy execution) as if it proved pre-turn write/tool authority.
Regression covers cross-turn bindings, replayed request identity, missing
final evidence, post-turn reconstruction and mismatched routing.

**Important**: The snapshot provenance label is a caller assertion, not
a cryptographic signature or validated DB transaction. Therefore these
synthetic tests do not yet prove real API same-turn parity. Next work must
capture a canonical immutable snapshot at the API boundary before execution,
bind it to the created Turn under the conversation session lock, then verify
its authenticated origin and compare target, scope, effect and side effects.
Never treat the `COMPATIBLE` result as permission to execute.

No default routing changes, API wires, tool calls, new storage writes, or
M3-C cutover are introduced by this work.
