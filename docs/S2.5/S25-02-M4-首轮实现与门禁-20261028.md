# S25-02 M4 首轮受控实现与门禁（2026-10-28）

## 基线、变更和边界

- 来源：main merge commit `65c8b90cf11bb137a10e9dc8456eb4b37303147b`，M4 设计分支 `design/s25-02-m4-unified-execution-20261028` 的设计提交 `6bd4268571914646176f4f051a74d1e2300f9fdc`。
- 实现分支：`feat/s25-02-m4-guarded-execution-20261028`。
- 本轮**不是统一决策路由全部接管**。只实现第一条受控、可回归的真实写入状态路径：取消已保存计划。
- 默认保持 `route_admission_mode=legacy`；`route_admission_mode=guarded` 是显式 opt-in，仅对已存在计划的取消请求执行额外的 pre-turn Host 候选准入；所有其他路由仍使用既有正式逻辑。
- `route_shadow_enabled` 继续仅做诊断，与该模式开关互不替代。M4 / M5 生产路由切换仍 HOLD。

## 本轮代码

1. `agent/config.py`：新增 Literal 配置 `route_admission_mode=legacy|guarded`，默认 legacy，不影响现有配置。
2. `agent/route_admission_m3.py`：支持 `plan_cancel` 的纯候选准入决策。明确要求当前有效 checkpoint、来源、保存计划引用和写入权限；返回 `candidate_execute`，**绝不单独授予执行权限**。
3. `agent/m4_guarded_cancel.py`：用请求本身的取消约束、独立模型语义确认与当前 Turn 身份/计划 revision 组成最小事实输入。只给出候选准入布尔结果，不调用工具或删除计划。
4. `apps/api/main.py`：在既有取消计划路径中，guarded 模式要求上述额外准入；不通过则返回安全澄清状态，不回退 AgentLoop；通过后依然只经原有 PlanStore CAS 在 Turn 终结事务中取消。
5. `tests/test_s25_02_m4_guarded_cancel.py`：默认开关、来源/快照/身份负例、API 创建→取消无工具调用。此处为 deterministic fake provider，不得等同真实 Qwen3 验收。
