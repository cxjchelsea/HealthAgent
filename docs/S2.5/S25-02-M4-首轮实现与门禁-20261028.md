# S25-02 M4 首轮受控实现与门禁（2026-10-28）

## 基线、变更和边界

- 来源：main merge commit `65c8b90cf11bb137a10e9dc8456eb4b37303147b`，M4 设计分支 `design/s25-02-m4-unified-execution-20261028` 的设计提交 `6bd4268571914646176f4f051a74d1e2300f9fdc`。
- 实现分支：`feat/s25-02-m4-guarded-execution-20261028`。
- 本轮**不是统一决策路由全部接管**。只实现两条受控、可回归的真实持久化路径：创建待执行计划，以及取消已保存计划。
- 默认保持 `route_admission_mode=legacy`；`route_admission_mode=guarded` 是显式 opt-in，仅对创建待执行计划、取消已保存计划执行额外的 pre-turn Host 候选准入；其余路由仍使用既有正式逻辑。
- `route_shadow_enabled` 继续仅做诊断，与该模式开关互不替代。M4 / M5 生产路由切换仍 HOLD。

## 本轮代码

1. `agent/config.py`：新增 Literal 配置 `route_admission_mode=legacy|guarded`，默认 legacy，不影响现有配置。
2. `agent/route_admission_m3.py`：支持 `plan_cancel` 的纯候选准入决策。明确要求当前有效 checkpoint、来源、保存计划引用和写入权限；返回 `candidate_execute`，**绝不单独授予执行权限**。
3. `agent/m4_guarded_plan.py`：在既有模型生成计划通过 `build_plan_checkpoint` 后，要求每个步骤的原始参数在当前请求文本中具有唯一、不重叠的可验证绑定，才进入待执行计划的原有 CAS 保存流程；无法绑定则安全澄清，不调用工具。
4. `agent/m4_guarded_cancel.py`：用请求本身的取消约束、独立模型语义确认与当前 Turn 身份/计划 revision 组成最小事实输入。只给出候选准入布尔结果，不调用工具或删除计划。
5. `apps/api/main.py`：在既有取消计划路径中，guarded 模式对计划创建和取消分别要求额外准入；不通过则返回安全澄清状态，不回退 AgentLoop；通过后仍由既有 PlanStore CAS 在 Turn 终结事务中保存/取消。
6. `tests/test_s25_02_m4_guarded_cancel.py`：默认开关、来源/快照/身份负例、API 创建→取消无工具调用。此处为 deterministic fake provider，不得等同真实 Qwen3 验收。

- `REMAINING` PASS：另一次 `calculate` 工具成功；第二步 completed（30），第一步未重复执行；`plan_execution_completed`。

## M4 guarded 安全验证增量（2026-10-29）
