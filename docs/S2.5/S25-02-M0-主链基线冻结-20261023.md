## 5. Non-negotiable behavioral/safety invariants

- Only one Host-admitted action may own the turn; model proposals never confer authority.
- Authenticated conversation ownership, request-id uniqueness and one running Turn per conversation.
- Tool registry, schema, registered-capability check and source-bound arguments.
- `respond_only` never silently gains write authority. Explicit current user source is required for actual writes.
- Formal plan creation is distinct from a written draft and from executing the plan.
- Saved-plan steps execute only under Host plan-control permission and valid checkpoint/scope; first-step requests cannot execute a subsequent step.
- A standalone read-only action must not mutate/resume saved plans.
- Pending clarification fills only the bound field of the original pending action; it cannot select a new tool or borrow stale consent.
- PlanLedger completion must follow successful matching real Observation.
- Invalid model/schema responses must not create side effects or manufacture tool evidence.
- Turn/assistant/plan local DB finalization has atomicity bounds; external effects are **not** proven exactly-once.
- Verified completed plan steps cannot execute again on replay; stale revisions fail closed.

These invariants are the M1/M2 acceptance oracle, not reasons to keep duplicate model classifiers.
