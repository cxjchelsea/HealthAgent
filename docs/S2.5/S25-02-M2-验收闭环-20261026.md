## 1. Implementation closure

- `TurnSemanticProposalV2` shadow remains disabled by default and executes only
  after legacy Turn finalization. It cannot control tools, persistence, plan
  transitions, or permissions.
- Short inputs include a zero-based Unicode code-point index guide. Effectful
  routes and authority-bearing evidence still require exact offset/text equality
  and fail closed. For `cancel`/`respond` only, optional `source_evidence` with
  uniquely occurring exact current-turn text may have its Unicode offsets
  deterministically rebound; absent or repeated text still fails closed.
- The semantic/Host boundary now distinguishes an omitted Host-owned pending
  field from a conflicting proposed field. Omission can be resolved only from
  one trusted pending field plus its original-request binding; conflicts deny.
- Deterministic Host preview now covers source provenance, tool registration and
  schema, plan schema/revision/step state, pending original request, read/write
  scope, replay/no-op outcomes, and the admitted-route vocabulary. It remains a
  diagnostic preview, not production authority.
- Same-turn API diagnostics reduce pre-turn trusted state and finalized legacy
  observations into bounded facts without using answer wording or raw model
  arguments. Responses now expose the actual `turn_id` separately from AgentLoop
  `run_id`.
- Live and physical reports record exact case, conversation, request, Turn and
  assistant-message identities. Physical readback prefers these identifiers and
  no longer relies on ambiguous historical prompt matching when IDs are present.
