# S25-02 全链路能力复盘与 M5 范围决策（2026-10-29）

> 性质：基于 main 现有代码和 S25-02 验收记录的**架构决策草案**。本文件不修改 API 行为、不许可默认路由切换、不等于 M5 实现授权。审查基线：main `e801dd3feb7b83ebc65592644809808ba91dabe4`。

## 1. 核验结论

**应开展 M5，但只做统一语义所有权、冗余分类器退役与集成验收，不新建一套 parallel Agent Runtime。**

M0/M1 建立基线及“一个主语义提案 + 独立 Host admission”的设计；M2 的分层语义与证据绑定为诊断范围 ACCEPTED，非正式执行授权；M3 的真实主链 pre-turn 捕获、路由诊断和若干 Host 门禁已集成，但 `agent/route_admission_m3.py` 仍标注 pure candidate / No API wiring，并未成为统一的正式 Invoker。M4 已经由 PR #24 Standard Merge Commit 合入 main，Post-Merge CI 691 passed/3 skipped，受限 guarded saved-plan 执行与 durable dispatch/recovery 为 CLOSED (scoped)。默认 `route_admission_mode="legacy"`，默认 `understanding_strategy="direct"`，Shadow 默认关闭；**不能据 M4 CLOSED 推导整条通用 Agent 主链已统一接管**。

**本轮没有测量 M5 前的真实运行时“每 Turn 分类调用次数”，故不能把静态调用点数当作实测冗余或宣称减耗。**

## 2. 正式 API 调用点审计（静态证据）

审计对象 `apps/api/main.py`（当前审查时约 1176 行）；以下为源码中可能存在的调用入口，而不是每个请求均会执行的固定序列：

| 路径/调用点 | API 源码行附近 | 现有作用 | M5 决策 |
|---|---:|---|---|
| `review_plan_cancellation` | 301 | 模型确认是否取消已保存计划 | 与主提案统一意图所有权；保留 Host 的取消 CAS、工具零执行检查 |
| `review_plan_intent` | 349、631 | 先识别计划执行，再复用或识别创建/继续 | 已有复用变量，不能仅凭两个代码位置判定双调用；用实际请求指标验证 |
| `review_plan_revision` + `check_plan_edit_intent` | 365、378 | 独立计划修订，失败/兼容性时复核 | 修订语义并入主提案；不删除具体步骤及参数绑定检查 |
| `UnderstandingService.understand` | 432 | 通用目标、约束、澄清语义 | 需明确它与计划意图的主次，避免两个互相否定的主分类器 |
| `classify_pending_reply`、`review_pending_reference_lookup` | 445、466 | 待补参数回答与检索意图 | 优先消费统一提案；保留未证实引用时的 fail-closed 再确认 |
| `review_unsupported_capability`、`review_read_only_clarification` | 485、498 | 不支持能力拒绝、只读澄清冲突 | 不可把未知工具放行；窄范围纠错可留，不得重新夺取主意图 |
| `review_plan_creation_reference`、`review_missing_plan_reference` | 644、652 | 保存计划与已有计划关联 | 可从统一提案抽取引用；Host 必须独立验证真实现有计划与当前请求 |
| `review_plan_execution_authorization`、`review_plan_execution_scope` | 717、735、781 | 当前轮执行确认及 FIRST/ALL 范围界定 | 将请求意图、范围一次提议；保留独立 Host 执行授权/作用域收紧（只可缩小不可扩大） |
| `evaluate_shadow` | 1055 | 提交后的诊断/对照 | 诊断与授权继续隔离，默认关闭，不算主执行语义调用 |

以上源码路径有条件分支，`understanding_strategy=direct` 与 `structured` 行为不同，M5 需分别建立基线；不得把关闭 Shadow 或删去安全检查伪装成降低模型调用的优化。

## 3. 建议的 M5 唯一工作包

**名称：M5 — 主语义提案收敛与冗余模型判定退役。** 在单一分支渐进实现，不重做 M1–M4。

1. **冻结可重演基线**：保存 main 精确 SHA、运行配置、模型标识、每个 Turn 的 provider HTTP attempts、延迟、真实 Host 路由结果、工具 trace、DB/Plan/Claim/Dispatch 读回；为 plan create/revise/execute_first/resume/cancel、pending、独立计算、MCP 检索、unsupported、冲突拒绝分别建正负样本。基线覆盖成功/拒绝/异常，不只记录最终 HTTP 200。
2. **单次主语义所有权**：复用已有 `ShadowRoute` / `UnderstandingResult` 语义定义，明确唯一当轮主提案、可信来源引用、目标动作、计划 scope、待补信息和不确定性；只在确实存在独立的模糊边界时运行定向复核，且必须记录触发理由及代价。提案绝不携带最终执行权限。
3. **Host 独立准入与渐进替换**：保持当前 Turn 身份、current-turn 来源、工具注册/schema、目标/计划引用、CAS/Claim/幂等、权限与 Final Invoker Fence；在显式 guarded 开关下按场景逐步消费统一提案并退役重复主语义分类器。对不支持的动作事前拒绝或保持已经选定的 legacy 路径；禁止同 Turn 已执行后再退回另一分派路径。
4. **集中验收与清理**：既有测试矩阵、隔离 DB/多 worker/重放/故障保护、Qwen3 未见表达、正负交叉案例及 AB/BA 新旧对照。确认后删除确实不再被引用的分类器与冗余 Prompt，保留可解释的拒绝码和观察指标。不趁机重写 AgentLoop 或业务能力。

## 4. 明确验收门槛（无需无限扩展测试）

- **安全硬门禁：0 unsafe**。不得出现计划只保存却提前执行、FIRST 越权执行下一步、无当前轮授权写入、跨用户串扰、重复副作用、伪造引用升级权限、CAS/Claim 失效、异常后自动重放不确定工具。
- **功能硬门禁：既有场景不得新增 P0/P1 退化**。新旧结果必须对具体工具名/参数/执行次数、计划版本与持久结果复核，而非只比较文本摘要或 200。
- **架构硬门禁：一个版本化主语义提案、一个实际主执行入口**。准入前可有必要的窄范围验证，但不得在两个模型分类器之间反复切换“真正的用户意图”；记录并说明任何再次询问模型的合理性。
- **效率验收：必须报告基线和改后 per-Turn provider HTTP attempts、P50/P95、失败率及功能成功率**。预期在典型计划路由上减少重复主分类调用；不预设必须优化固定百分比，也不允许通过删掉安全验证来减少调用次数。真实模型样本少时不得宣称统计显著。
- **兼容性门禁**：legacy 默认为关闭 M5 新执行权，支持事前回退；不能为 M5 范围外写工具声称 exactly-once。Shadow 继续只能做独立诊断。
- **退出证据**：精确 HEAD CI 全绿、真实 Qwen3 原始结果、DB/Claim/Dispatch 读回、独立审查和经用户确认的 PR/合并授权。保持 main 默认 legacy 直到单独的上线决策。

## 5. 不属于 M5 的任务

不做 S25-03 Goal/TaskState/Artifact，S25-04 动态工具选择，S25-05 Tool Registry；不扩充通用多 Agent Scheduler/长期记忆；不做外部非幂等写入的全局 exactly-once；不自动切生产默认路由；也不把 M2 Shadow 诊断的候选准入当作真实权限。

## 6. 设计评审决策

**建议：M5 GO FOR DESIGN；HOLD FOR IMPLEMENTATION。** 下一步以本文件为输入，针对“主提案产出 / Host 权威来源 / Final Invoker”的接口方案做一次审查后即可进入一个集中实现工作包，无需再次拆为多级 M5-A/B/C 或反复重复 M2 的分类器专项微调。

若进一步静态+运行时审计证明当前 guarded 路由已经满足单一主提案、没有实质重复主分类，则允许把 M5 缩为删除无用逻辑和集中回归后直接关闭；**不为完成编号强行增加代码。**
