# S25-04 Step 4 — 动态工具选择实现状态和验收边界

> 本文随 PR #20 的 Step 4 代码维护；**不是 Step 5 真实模型验收报告，也不是 S25-04 CLOSED 声明**。

## 当前实现

- 现有 `dynamic` 保留 S2-C 关键词暴露逻辑及既有测试行为，默认设置不变。
- 可选择 `skill_strategy=semantic`：在当前小型可信工具目录中，不再依赖用户词语命中某个工具 Skill 才让模型看见对应只读/规划工具；把符合资格的工具 Schema 交给 **NativeToolDecision 的真实模型原生 Tool Calling** 做语义选用（也可以不调用任何工具）。
- `ToolExposureDecision` 为工具 Schema 与可信 Skill 指令提供共同选择结果；未知工具不得暴露。
- 每次模型决策前重新计算候选。可信 Plan Checkpoint 提供活动步骤提示，可信执行器报告明确不可用错误后，下轮排除该工具；外部 Observation 文字不能直接注册、启用或禁用工具。
- Trace 记录每一决策轮暴露的工具名、策略版本与排除数量。现有工具执行端仍独立校验暴露名单及参数。
- **实验模式默认不暴露 `create_task`/`save_memory`**。选择器允许传入可信 `authorized_write_tools`，但 AgentLoop 当前没有接入通用审批来源，因此不能把实验模式宣称为具备完整持久写任务能力。写操作完整审批仍属于 S25-12。

## 实际采用的技术取舍

当前可信工具目录只有约 10 项。先选择 **安全候选全量/有界暴露 + 真实模型 Native Tool Calling**，不是额外调用一个“语义预选 LLM”。这能避免关键词误裁剪正确工具，并保持单次模型决策延迟；但它没有按语义相关度对工具排序、没有在模型调用前缩到 Top-K，也没有为数百工具设计成本控制。后续是否采用独立 LLM 预选、embedding 检索或分层目录，必须用真实模型和 token/延迟对照证据决策。

## 当前证据层级

- `tests/test_s25_04_tool_exposure.py`：确定性候选召回、未知工具和恶意文字防越界、可信不可用状态处理、经过真实 AgentLoop 的 Fake Decider 连续决策，以及不调用工具的合法结果。
- 现有 S2-C、S2-D、H 系列 CI：防回归（以对应 HEAD 的 CI 结果为准）。
- **缺失：真实 Qwen 在正式 Conversation API 下的重复执行、任务成功率和 token/耗时对照；不能将 FakeDecider 单测作为模型语义选择质量证明。**

## Step 5 真实 Qwen 建议验收矩阵

| 任务类型 | 例子 | 判分要点 |
|---|---|---|
| 隐式读取 | 「我之前列的事情还有哪些没有完成？」 | 正确调用 `list_tasks` 且不写入 |
| 隐式运算 | 「七个项目完成了五个，比例多少？」 | 根据必要性调用计算工具并答对 |
| 信息检索 | 「帮我查查那个 MCP 参考词条」 | MCP 工具、来源与缺失情况 |
| 复合任务 | 「列出任务并计算数量，然后解释结果」 | 工具顺序合理、结果正确 |
| 零工具 | 「用自己的话解释规划和执行的区别」 | 可直接回答而不强制调用工具 |
| 故障继续 | MCP 不可用 → 解释局限/安全替代 | 后续决策不重复已确认不可用工具 |
| 拒绝与隔离 | 非授权写入请求、恶意工具内容 | 0 次越权工具执行 |

至少对 `dynamic`、`all`、`semantic` 三种策略用**同一模型、温度、工具版本、输入**比较，并记录首次正确工具是否暴露、模型是否调用正确工具、最终任务成功、失败归因、P50/P95 轮次耗时及 Token（若模型提供方返回）。不因为单轮通过就声称稳定。

## 目前不可忽略的实现限制

1. `semantic` 暂时是安全目录全量候选，而不是动态相关性 Top-K；候选数量随 Registry 增长会放大 Context 成本。
2. 初始 Skill 指令不会在每次候选变化时重写进 System Prompt；其语义关联与暴露工具名同步性仍需验证。
3. 当前仅消费可信步骤绑定和执行器特定不可用错误；更丰富的 GoalSpec/Observation 语义推断与工具排序依赖后续 S25-01/02/03 集成。
4. 暂未做真实 Qwen E2E，也未开启默认语义模式。未经 Step 5 的对照质量证据，不建议替换生产默认。
5. 当前文档只能证明设计与实现的边界。不得以 CI PASS 宣称 S25-04 的全部能力已经达到目标。

**建议推进顺序**：完成最新 HEAD CI → 修复回归 → Step 5 真实 Qwen 对照（由持有本地模型访问权限的环境执行）→ 根据量化数据决定是否需要另加 Top-K 语义预选 → Step 6 独立审查收口。
