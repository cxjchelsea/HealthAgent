# S25-02 Step 5 — C02/C03 Arithmetic Recovery & Policy Boundary (2026-10-23)

基线 PR #22，未合并 main。

## 真实模型验收证据

用户 C02 输入要求用工具计算 `2**10`，如果不支持则转换为等价乘法。Qwen/AgentLoop 真实执行：
- Step 1 `calculate` → `unsupported_expression`、`ok=false`
- Step 2 `calculate` → `ok=true`，数值 1024
- Step 3 final → 1024
- 但旧基线返回 `partial/unresolved_tool_failure`，因为失败追踪按参数级别，仅同一参数成功才能清理旧失败。
- 同次 `execution_mode=execute`，只读计算却被过度归类为允许写操作模式，虽然本次没发生写入。

## 修复 1：有界、工具证据绑定的同一算术目标恢复

新增 `agent/arithmetic_recovery.py`，解析有限 AST 为精确 Fraction；算子仅加减乘除、有限整数非负幂，限制长度、树大小、深度、数值规模，不用 eval，不执行任意代码。

在 `agent/loop.py` 中为未解决的计算失败记录有限错误类别，仅对 `unsupported_expression` 的旧失败，当新的 `calculate` 工具成功且**先前表达式与新表达式在有界精确算术下等价，并且新的工具真实返回值也一致**，才删除对应的旧失败记录，并记录 `arithmetic_failure_recovered`。这不是“任意一个成功清除全部失败”。

保护：
- C01 `10/0`：除零没有可验证数值，不解除失败；
- C03 `8/0` 失败 + `2+2` 成功：不同目标，仍 `partial`；
- `2**10` 失败 + `2+2` 成功：非等价，仍 `partial`；
- 只接受真实成功 Observation，模型自己的 final 宣称不算证据；
- 该方法当前只覆盖数学表达式等价，**不冒充通用 Agent 任务/计划级完成证据系统**。

## 修复 2：Execution Policy 不应过度授权计算

新增 `verify_execute_policy`：正式结构化 API 中若独立策略返回 `execute`，用受约束模型对原始用户输入判定是否明确请求真实写入/持久化；若没有写入意图，降为 `read_only/tool_action`，不得授予额外权限。保持 S25-01 的 `respond_only=[]` 和写工具原有授权门禁。该安全复核依赖真实模型准确性，不是不可错的确定性语义证明。
