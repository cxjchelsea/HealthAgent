# S25-02 Step5 M2 — Shadow-Only Route Evaluation (Implementation Report)

Status: **M2 IMPLEMENTED FOR OPT-IN OBSERVATION, NOT ACCEPTED FOR CUTOVER**
Branch: `feat/s25-02-s25-01-main-integration-20261022`, PR #22 draft.

## Implemented
- `agent/route_shadow.py`: a V2-labeled primary-route semantic proposal with strict Pydantic routing-combination constraints. It produces only diagnostic labels and conservative `host_would_deny` hints; **this is not the full proposed M1 source-reference/authority schema or full Host admission matrix**.
- `Settings.route_shadow_enabled = False` by default.
- `apps/api/main.py`: optional shadow model call **after** successful legacy Turn finalization and database commit. It cannot influence this turn's tool exposure, PlanLedger, GoalStore, TaskStore, authorization or final Turn result. No persistent shadow effects. Only sanitized route labels, elapsed time and exception class appear in the optional response metadata.
- Failure of shadow provider, bad JSON or ungrounded source quote returns `state=unavailable`, not a route.
- `tests/test_s25_02_m2_route_shadow.py`: standalone mock-provider validation, missing-checkpoint hint, malformed combination, ungrounded quote and provider failure.

## Operating and security bounds
- This initial implementation is a bounded **diagnostic shadow**, not a production alternate. It does **not** cut over old routing, eliminate classifiers, change `UnderstandingResult v1`, or grant new tool permissions.
- Run only in a development / isolated acceptance environment with real model, explicit opt-in `ROUTE_SHADOW_ENABLED=true`. More model calls and latency are expected with opt-in.
- No raw model output, user content, previous conversation or tool credentials are included in shadow response metadata.
- A shadow attempt occurs only for successfully finalized structured requests using a live provider, with no injected fake decider and no explicit goal_confirmation. Error/503 routes are not evaluated by this initial opt-in hook.
- The shadow result reflects **post-commit timing** but is classified against the **pre-turn** `existing_checkpoint`; it can therefore compare semantics but not exercise authoritative post-turn admission.
- Bounded call time is 12 seconds; this opt-in response latency increase must be measured before any automatic enablement.

## Missing evidence and M2 exit gates (OPEN)

1. Expand `ShadowRoute` into fully validated M1 `TurnSemanticProposalV2`: exact source offsets and explicit negative constraints, typed reference/step, trusted pending original field, clarification reason/question, goal/goal-change consistency.
2. Add a full deterministic **hypothetical** Host admission engine for every route and existing state; the current `host_would_deny` only checks basic checkpoint/pending existence.
3. Compare each shadow proposal with the **actual legacy admitted route**, actual tool names/arguments, status, and before/after store readback; current metadata does not establish this evidence.
4. Cover errors and early-return flows through independent shadow replay, without risking any extra effect or changing legacy response; keep owner-scoped diagnostics private.
5. Measure route confusion, unsafe hypothetical admissions (target zero), unnecessary clarifications, model-call counts, and p50/p95 latency across multiple paraphrases.
6. Run Qwen against the opt-in shadow and capture auditable case-ID/conversation-ID/request-ID links. GitHub CI mock tests are not proof of these real-model metrics.

**Decision:** this increment satisfies *shadow integration scaffold* only. M2 formal exit remains HOLD pending those gates. M3 cutover and Step 6 explicitly NOT AUTHORIZED.
