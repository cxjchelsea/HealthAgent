# S25-02 M4 恢复边界与架构复审（2026-10-29）

状态：VERIFYING / HOLD。默认 legacy，不授权合并 main 或接管生产。

## 已实现及可证实的部分

- Guarded 路径的计划创建、分步执行、继续、取消：Qwen3:14b 首轮 5/5 PASS；独立变体 + 同请求拒绝 + 真实 HTTP 并发：9/9 PASS。
- 本地 SQLite readback：27/27 PASS（API 是否始终指向相同实际 DB 路径由操作者确认）。
- 通过 CI 的 PostgreSQL 行锁 Claim/CAS 专项测试；不等价于 Qwen 多进程生产式 E2E。
- 工具执行后至 checkpoint 持久化前出现受控异常：当前 guarded 模式在本轮取得执行 Claim 后将 Turn 的 failure_code 设为 plan_execution_outcome_unknown。后续执行请求在进入 AgentLoop 前发现该持久标记时返回 plan_execution_reconciliation_required，禁止自动二次派发。
- 这次补齐 checkpoint CAS 冲突时相同的不确定性标记，避免报普通冲突却允许下一个新 request_id 继续执行。
- 新增 GET /conversations/{cid}/plan/recovery-status：所有者范围内、只读，仅给出有无 running Turn、未知结果 Turn、Claim 和计划记录；不暴露工具参数；不删除 Claim、不自动重试。普通请求仍被正在运行的 Turn 的唯一约束挡住。

## 安全边界与人工核对流程

1. 若 recovery-status 报 reconciliation_required，停止向该会话发新的执行请求。观察数据库 Turn、PlanExecutionClaim、PlanSnapshot 的原始身份与时间，结合外部工具的真实调用日志确认是否产生效果。
2. **不能依据一个 pending Checkpoint 就断定未执行**。工具调用与数据库提交不在同一事务；响应丢失、进程突然退出、数据库提交冲突，都有可能留下工具已执行而 Checkpoint 未推进的状态。
3. 此次没有开放自动解除 Claim、自动重放或单纯由普通聊天文字批准恢复的接口。人工恢复必须由后续单独设计的可信操作权限、工具回执和 CAS 原子审计流程完成；审计前保留隔离/阻断，不建议直接修改 SQLite 或 PostgreSQL 表。
4. 只读检查接口是发现问题的入口，**不是恢复完成动作**。进程崩溃后仍为 running 的 Turn 可永久阻断会话；需单独的安全维护工作流，不得声称已经具备自主恢复。

## 独立架构审查结论

- **P0，未完成**：突然进程崩溃/断电后 running Turn 和 Claim 的有证据受控清理与恢复、含多 worker 争用下的不可重复副作用保证。现状“停住不自动重试”是 fail-closed，而不是可用性恢复。
- **P0，未完成**：外部工具副作用的请求级 durable dispatch/outbox/receipt。现有 ledger 和 Trace 只记录受控正常路径证据；不能证明工具执行后进程失联时 exactly-once。
- **P1，未完成**：手工确认结果后有明确管理员权限、不可抵赖审计和双重状态 CAS 的受控恢复接口。
- **P1，未完成**：真实 PostgreSQL 双 worker API 竞争+进程 kill +物理 SQL 读回；此前 PostgreSQL CI 为 Claim 行锁的确定性验证。
- **P1，未完成**：guarded vs legacy 相同请求下的模型调用次数与 P50/P95 时延比较、Shadow schema 不合法组合比例与策略。
- 当前 Shadow diagnostic 偶发 invalid_shadow_route_combination；诊断模型的无效提案不得被自动修补为授权，更不能直接影响已提交工具结果。
- API 原异常兜底将已取得执行 Claim 后的受控异常保守记为未知结果；因此部分“仅工具调用前”异常也可能变成待人工核对，属于安全优先的可用性取舍。

**结论**：M4 已通过有限计划路径功能和部分失败/竞争测试，**但“全部边界完成”不成立，M4 不可 CLOSED 或进入生产默认 guarded**。不得把持续阻断当作已经实现人工恢复或 exactly-once。
