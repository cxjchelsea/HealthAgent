## 1. 本次审计确认的事实

1. 正式入口 `apps/api/main.py` 仍串联独立的 saved-plan/cancellation/revision 分类、Understanding、clarification、execution-policy 再确认及 `AgentLoop`。发现至少两处 `review_plan_intent`（前置与后续复用）、一次独立 `review_plan_revision`、一次 `review_plan_cancellation`、一组 execution policy 分类与 reconcile。它们不是一个统一的、已具执行权的分派器。
2. `agent/route_shadow.py` 已覆盖 `plan_create/execute_first/resume/revise/cancel` 和 `plan_cancel`，但 `evaluate_shadow` 作为后验诊断执行，`compare_to_legacy` 只作观测对照，不能作为真实路由授权。
3. `agent/route_admission_m3.py` 为纯 reducer；`candidate_execute` 明确 **不是** 调用工具的权限，模块注释亦说明 **No API wiring**。当前没有可直接安全打开的统一执行开关。
4. `agent/m3c_shadow_admission.py` 将 request freshness / session lock / idempotency authority 固定为 false；这是有意的 fail-closed Shadow 契约。直接拿该结果做正式准入将拒绝真实执行。
5. 正式 Saved Plan 已有 `ConversationPlanStore` 快照 CAS、执行占用 claim，以及 Host 所属的取消流程。计划取消不应退回普通 `AgentLoop`；取消本身是持久化状态变更。
6. `agent/config.py` 目前只有 `route_shadow_enabled` 诊断开关，不存在安全的 M4 production admission 开关。不能用现有 Shadow 开关代替。
7. M3 证据：PR #23 合入 main；最终精确 HEAD CI SUCCESS；真实 Qwen3 的计划创建/修订/第一步/剩余步骤、取消与不提前调用工具通过。M3 `PASS WITH LIMITATIONS`，非生产切换许可。

## 2. 精确的缺口（按风险而不是按文档数量）

| 缺口 | 当前状态 | M4 验收目标 |
|---|---|---|
| 单次语义提案 | 重复分类和解释路径 | 同一 Turn 只生成一个版本化主语义提案；结构化约束检查与业务授权保持独立 |
| 真实 Host admission | 仅有不执行的 reducer + Shadow bridge | 用不可变的事前 Turn/计划/待补来源和工具注册事实做 admission，并连接最终 invoker guard |
| 取消语义 | 业务 Host 正常，Shadow 只作诊断 | 在候选提案→准入→CAS 事务中证明取消既可授权又不执行工具 |
| 边界一致性 | post-result comparable ≠ exact authorization | 证明无作用域扩大、无自作授予写权限、无未绑定的工具参数 |
| 回滚安全 | 没有正式开关 | 默认旧路径；可关停的单路由试验开关；同 Turn 不能两路各执行一次 |
| 成本与效果 | Shadow 记录自身调用和时间 | 报告旧路径 vs 新路径的模型调用总次数、超时/失败、延迟与最终状态 |
| 独立验收 | M3 测试偏重修复语句 | 固定且未用于 Prompt 调优的变体、真实 Qwen3、Postgres 并发/持久化读回 |

## 3. 建议的最小可实施架构

`Turn 创建+唯一请求约束`
→ `CapturedTurn（只读事前快照）`
→ `SemanticProposalV2（唯一的模型语义提案）`
→ `Host Admission（验证原文来源、目标和 scope、注册工具 schema、当前授权、freshness、lock、CAS revision）`
→ `Final Invoker Gate（对具体参数和动作作最终检查）`
→ `Existing AgentLoop / PlanStore / TaskStore`
→ `Observation → 原子 Turn/消息/计划状态提交`。

约束：
- 一个 Turn 最多一条**正式执行**路径，不能“新路由失败则隐式回退旧路由继续执行”；试验回退只能发生在任何 side-effect 前。
- `deny/clarify/noop` 不产生工具副作用；`candidate_execute` 只提供候选，不能触发调用。
- 保留 `request_id` 幂等、正在执行的 Turn 互斥、精确 preturn checkpoint revision、Plan claim、CAS、用户隔离与写操作权限。
- Shadow 分类失败不影响生产；模型不能通过产生 `source_quote` 或 effect 标签自我授权。
- 计划创建只保存不执行，继续执行需逐步精确授权；取消计划必须持久化删除或有明确状态终结且可独立读回。
- 不能用关键词路由代替语义分类；确定性文本检查限于否定约束兜底与安全验证。

## 4. 实施方式：一个工作包，不新增细碎里程碑

**设计审查之后**再建立单独实现分支；保留当前文档分支作为决策记录，不在设计阶段改动生产端点。

- **现状基线与可观测性**：冻结旧执行路径的整套场景、错误率、模型调用量、时延、追踪与失败原始证据。每条记录固定 commit、model、配置、会话/Turn/请求 ID，不混用 CI mock 与真实模型结果。
- **统一提案 + Host 事实接线**：复用 `ShadowRoute` 类型及 `CapturedTurn`，为 `PreTurnFacts` 增加可信来源填充器；完善 plan_cancel 独立准入、模型不可见的工具注册和参数核验，并以 `candidate_execute` 之后的正式 invoker gate 终结权限判定。严禁复用 M3-C 的后验 facts。
- **受控接管**：添加独立默认关闭的 `route_admission_mode=legacy|guarded`，仅先允许获证实的只读计算/检索及保存计划；随后再纳入 plan revise/execute/cancel 和澄清。每个新增 route 都有同时验证的负例。对不支持的 route 先保留 legacy，必须在请求入口**事前选定单条路径**。
- **物理验证**：现有 D03/D05/D06/E03/E04/E06/F02/F03/F04 矩阵 + 取消、并发、多实例请求、重放、过期 revision、错误/超时、不同用户、权限拒绝、跨轮保存事实。Postgres 真数据库验证和独立未知表达的 Qwen3 重跑至少两轮，不因单句 PASS 宣告泛化通过。
- **验收对比**：必须提供执行身份/工具参数/次数、完成证据、状态变化、拒绝原因、独立模型调用/延迟统计、旧路径等价性与回退条件。如果新路径增加 unsafe 或不能收敛重复解释，则不进入 M5。

## 5. 验收门禁与中止条件

**继续实现前需审批**：该设计、受控开关策略、单 Turn 单路由、允许接管的分步范围；不等于授权生产切换。

**M4 PASS（具备申请 M5 的资格）**：
1. CI 全绿（精确 HEAD）；关键路径单元/集成/DB/CAS/权限/多 worker 并发无阻断。
2. 真实 Qwen3 至少两轮独立变体，计划创建→修订→第一步→剩余→取消及 standalone tool/task/pending/拒绝场景，所有关键安全负例 0 unsafe。
3. 新旧路由对照核对具体 scope、实际工具参数、持久化/外部副作用、幂等和来源；不把 `compatible_plan_execution` 当严格一致。
4. 记录可比较的模型调用次数、P50/P95 延迟、出错率；不将无凭据的提速判断记为结果。
5. 演练开关关闭和业务回退；回退不得发生在外部副作用已发生之后。保留 Shadow-only/HOLD 直到单独获得 M5 授权。
