## 3. 系统性复审问题
**A. 对象决策。** 第一阶段由模型判断当前用户意图；第二阶段受对象专属 operation schema 约束。要求比较多步骤持久计划与单独持久事项、正在回应 Pending 的参数与新独立工具请求。保持 `ROUTE_BY_CORE` 不依赖关键词覆盖，不允许宿主改写对象。

**B. 步骤引用与失败类型。** `extract_unique_ordinal` 现有范围面向 `第[一二三四五六七八1-8]步`，不天然覆盖英文字面形式；先整理不同语言原文 Span、步骤编号、checkpoint step 数、source provenance、revision_valid 和 bound_step_valid 的适用顺序。无法验证必须 fail closed；不要为了分数将所有 deny 改 needs_evidence。

**C. 取消来源。** 分类正确不代表有足够当前回合来源证明。安全的只读 preview 可以采用可信消息字面来源作为候选，但必须严格隔离 `cancel` 诊断与真实中断/状态写入。缺少用户当前操作来源时不能假定可提交。

**D. 验收标签审计。** 独立标注人分别检查这八条原文及可信 facts，尤其计划/事项边界、英文步骤引用和取消是否按现有 Host 合同应当 `safe_non_effect`；标注分歧记录为 disagreement，不得回填原卷改分。当前既定结果保留。
