## 不可突破的边界
1. 前置仲裁只选处理域，不是执行授权；create_task、save_memory、MCP 参数仍由 Host / AgentLoop 独立校验。
2. 已进入 M5 并发生绑定拒绝的请求必须保持拒绝；不得再依赖第二次模型判断降级执行。
3. 计划引用、混合请求、证据不足的请求不得被普通工具路径自动接纳；需走计划检查或澄清。
4. 不允许关键词匹配或纯自由文本分类决定高风险写工具权限；分类结果与当前轮、宿主保存状态绑定。
5. 默认 dynamic 与现有 guarded/structured 安全契约不得因 Top-K 试验而变化。

## 前置仲裁方案（设计，尚未实施）
先引入有类型的候选提案：ordinary_tool | plan_control | ambiguous，要求本轮唯一逐字证据片段，且绑定 Host 保存计划快照。仅对明确 ordinary_tool、无计划引用且通过保守的独立一致性检查的请求绕开 M5 新计划创建提案，继续进入既有 structured understanding、execution policy 和 AgentLoop；不授予执行权限。其余均保留 M5 或澄清处理。**尚需论证模型把实际计划请求误判为 ordinary_tool 时的安全性；在这一风险关闭前不启用该分流。**

## 需要新增的回归矩阵
- 普通任务创建、明确记忆同意/未同意、只读检索：可正常走相应 Host 许可流程，并验证真实持久化/无持久化。
- 明确 CREATE、FIRST、RESUME、REVISE、CANCEL：仍属 M5 所有；无法绑定时拒绝且无副作用。
- 模糊计划、计划与普通写入混合、模型提案和 quote 不匹配、重复 quote、模型错误/超时：无越权回退。
- MCP 查询：精确 term 必须来源于用户原话，模型虚构参数保持拒绝。
- provider empty_decision：仅记录有界元数据，不输出原文，不自动补写工具。
