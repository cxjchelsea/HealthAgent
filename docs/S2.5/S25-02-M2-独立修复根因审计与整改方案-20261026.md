## 根因分解

### RC1 语义输出任务负载过重
同一次模型输出须决定 primary_route、route_target、reference、execution_scope、effect_intent、clarification、用户文本的 Unicode 精确 span 等。将自然语言语义识别与机器精确偏移坐标绑定，会把一个语义正确提案因字符计数失败转换为 unavailable；也会形成模型选择正确路由但 effect 错误的组合。Schema 合法不等于语义合理。

### RC2 单任务 / 正式计划 / 修改计划三者边界不清
v5_task_cn_1 把一项正式待办误判为 plan_create；v5_clarify_revision 在修改对象/范围不明确时提议 plan_revise。根源更像是 route family 选择依赖表面措辞、缺少可靠的对象和目标状态约束；当前证据不能证明唯一原因就是 Prompt。不能用关键词把提案硬改成另一路由。

### RC3 Pending 是一个带来源的延续行为，而非独立新任务
v5_pending_term/expression 的 route 对，但 effect 为 none，导致模型在上下文接续与实际工具效果上发生脱节。效果应由已验证的 Pending 原请求和已注册工具契约限定；不能从模型的 none 声明直接执行，也不能由 Host 静默把 none 修复为 read_only。缺失或冲突时 fail closed。

### RC4 Host 预览不应混淆“提议”与“准入”
heldout_v5 中两条 Pending 每轮各出现一次 effect 失配的 potentially_admissible。最新原分支已有显式拒绝规则，但它是 post-result 纠偏，还没有独立测试证明泛化。M2 Host Facts 可以来自 fixture/legacy observation，只能支持诊断；M3 的事前授权必须独立绑定当前请求、工具 Schema、持久化 checkpoint 和幂等锁。

### RC5 验收泄漏与观测偏差
五条 Prompt 与测试字面重合，连续开发期间多个所谓 held-out 集又受到先前失败反馈影响，导致 PASS 指标高估泛化性能。CI 默认 fake model 只能验证程序契约，不会发现真实 Qwen 行为误判。

## 整改顺序（应一次审查总体设计，而非无止境拆补）

1. **先冻结验收政策**：v1-v5 报告只读归档；区分 dev examples / tuned regression / independently blind；新的独立题库由与 Prompt 调优隔离的作者或规则生成并先封存 hash，真实评测后严禁改题/改标签。至少两次抽样，95% 每轮，critical cases 全过，unsafe=0。
2. **解耦语义与证据定位**：模型输出候选 route、目标/对象、预期行为、关键原文 quote；由确定性的 Host 在 *唯一且可定位* 的原文上生成 offsets 并校验。重复片段、跨消息引用、缺失或含歧义来源必须拒绝，不能拿“重定位成功”作为授权；修补机制仅面向可选诊断证据，作用域明确。
3. **明确语义状态机决策表**：单工具任务与持久计划分别定义充分条件；plan_revise 必须具备有效计划、明确修改对象、具体 change 和未执行约束；缺失时 propose clarify。先针对同义表达、否定约束和对抗歧义做多轮回归，而不是关键词路由。
4. **Pending 延续显式契约**：把 pending original request / tool schema / expected effect 作为可信上下文，不让模型重新“创造”工具效果；模型只解释补充值和上下文指向，Host 对 effect 是否与该工具权限/参数一致做严格判定。unknown effect -> needs_evidence，不自作修补。
5. **Host Preview 两道门**：提案结构与原文指向有效性；可信执行约束/效果/步骤范围核验。M2 输出只可 potentially_admissible 诊断，不提供执行 authority。拒绝场景必须做负例测试。
6. **有代表性的回归 + 盲测**：覆盖 v5 四类失败、英文/中文变体、任务转计划/计划转待办、缺失计划、待补参数取消与更新、同字段冲突、未注册工具、只读/写入权限、Unicode 重复引用、多轮会话隔离；记录 route/effect 双混淆矩阵、拒绝原因、模型调用和版本 hash。
7. **收口分支并集成**：先确保修复分支 CI 与真实模型回归通过，再运行独立盲测、同轮 API 和物理读回；只有所有 M2 门禁通过后才讨论恢复 M3 并移植变更。不要提前 cherry-pick 原分支末尾两个大提交。
