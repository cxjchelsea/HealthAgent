# S25-02 M3 — Host Single Admission Cutover design and gate

Baseline: M2 accepted for Shadow-only against commit `94adfe8a70580c81208888acd4c57374491b1abd`.
Status: **M3 DESIGN + ISOLATED CONTRACT IMPLEMENTATION; PRODUCTION CUTOVER NOT AUTHORIZED**.

## Scope
One unified route proposal (`ShadowRoute`) must go through one deterministic
admission decision before **any** branch-specific operation. Semantic output
and model source spans are untrusted. Do not invoke the legacy route afterwards
as a second competing dispatcher. Preserve checkpoints, plan revision CAS,
tool allowlist/schema validation, request idempotency, session locks, safety
and source/write restrictions.

## Inputs (pre-turn, trusted only)
- immutable conversation/turn/client request identifiers
- pre-turn checkpoint identifier, revision and per-step state
- verified pending action, pending field and original request authority
- current user input binding and operation-scoped constraints
- registered tool schema and validated concrete arguments
- capability/effect permissions, write provenance and idempotency state
- immutable proposal fingerprint and an explicit execution-mode feature gate

Do **not** infer these facts from a completed legacy outcome. M2
`facts_from_legacy_observation` is post-turn telemetry only, never M3 input.

## Output
One versioned `AdmissionDecision` with disposition `deny | clarify |
noop | execute`, approved route target/scope/effect, context fingerprint,
read-set/checkpoint revision, tool proof where needed, and typed denial reason.
The decision must not contain executable capability when evidence is missing.

## Security invariants
1. Deny or clarify on untrusted, expired, mismatched or incomplete proof.
2. Unknown tools and forged pending/checkpoint bindings cannot execute.
3. Writing requires current-turn source and authorization; no inference from
   earlier success or `execution_mode` alone.
4. Plan step scope never widens; exact revision and step set must match.
5. Repeat request or stale concurrency snapshot cannot repeat side effects.
6. An effectful model route with `route_target=none` must deny.
7. Cancellation is a scoped state transition when it alters Pending/plan
   state; it is not automatically a side-effect-free text response.
8. Diagnostics are separate from authorization, and failures remain typed.
9. Default to legacy until separately reviewed and authorized; no implicit
   fallback to legacy after M3 has committed a side effect.

## Delivery sequence
- M3-A: immutable pre-turn facts adapter, strict admission contract,
  pure deny/noop/clarify/execute reducer, invariant tests.
- M3-B: read-only dual-run parity and refusal/no-op/plan transition matrix.
- M3-C: gated implementation of single dispatch point, without removing
  existing independent permission and recovery guards.
- M3-D: real Qwen/API physical E2E, tampering, concurrency, idempotent replay,
  failure injection and exact Turn/DB readback.
- M3-E: explicit authorization to enable and remove competing dispatch;
  rollback before side effects, not after partially applied writes.
