# S25-01 — 真实模型门禁与默认主链切换决策

状态：**真实 Qwen 尚未实际运行；暂不可关闭 S25-01 或改变所有用户的默认执行路径。**

## 当前入口

- `UNDERSTANDING_STRATEGY=direct`：保留原有 Agent 决策链作基线，避免凭臆测给每轮增加结构化模型调用。
- `UNDERSTANDING_STRATEGY=structured`：同一正式 `/conversations/{cid}/agent/messages` API 先使用唯一 `agent/understanding.py` 生成 GoalSpec；校验并装配已确认 GoalState 后交给既有 Agent Loop。存在必要澄清或更正确认时暂停，不执行工具。
- 两条策略是**同一产品的对照执行模式**，不是两个并行的 Understanding 实现。最终默认切换需要真实质量和延迟证据，不可因为假模型 CI 全绿而宣布完成。
- 结构化模式在 AgentLoop 选用已注册工具全集；这里未完成 S25-04 的语义能力检索与工具治理，若工具数量增长需进一步测 prompt budget。

## 本地真实 Qwen 运行方法

确保使用真实且可访问的 Ollama/OpenAI-compatible 服务，预先下载模型。本机 Windows PowerShell：

```powershell
$env:RUN_S25_01_LIVE="1"
$env:MODEL_PROVIDER="ollama_proxy"
$env:MODEL_BASE_URL="http://127.0.0.1:11434"
$env:UNDERSTANDING_LIGHT_MODEL="qwen3:4b"
$env:UNDERSTANDING_STRONG_MODEL="qwen3:14b"
python -m evals.s25_01_live --output s25_01_live.json
```

若实际使用的是代理而非原生 Ollama，按本地已验证的 `MODEL_BASE_URL` 填写，模型名称必须与服务上可用的名称一致。运行命令和 JSON 证据应保存在本地或专门评测目录，不上传含私密输入的完整请求/响应。

该脚本包含固定案例及同义表达，实际向 provider 发请求，不使用 FakeProvider。其评分是**场景标签的启发式断言**，不等同临床安全、通用语义正确性或完整 Agent 能力验证。

|---|---|---|
| 结构化语义模型对照 | 4B、14B 对同一组任务理解的准确性、歧义澄清、约束保持、多轮目标变更；分析错误输出并提供人工复核 | **待真实模型** |

| 默认模式回归 | 正式 Conversation API 真实多轮任务、确认/拒绝、权限拒绝、工具失败、Checkpoint、用户隔离和对抗输入；结构化模式不得降低正确性或破坏安全门禁 | **待端到端验证** |

## 默认策略切换门禁

在完整对照之前，**不得**把结构化模式设置为所有环境默认。切换前需同时满足：

1. 真实模型任务通过预先约定的准确性、误澄清、漏约束与越权行为门槛。尤其明确约束更正和有副作用任务不得由模型“猜测确认”。
2. 记录完整请求的延迟与资源，含两模型同时加载和换载代价。小模型单次更快不等于整轮更快。
3. 经旧 S2 和新增 S25-01 测试回归，旧特判对应逻辑有退出证据；不允许新旧关键词理解器长期共存。
4. 显式切换 `UNDERSTANDING_STRATEGY=structured` 在受控环境真实演练，经复核后才修改配置默认值。保留受控紧急回滚能力，但不是长期两套业务意图理解。

现有 CI 的 deterministic pytest/Benchmark 仅能证明代码行为与工程接线。未取得真实模型完整证据时，S25-01 状态保持 **IMPLEMENTING / VERIFYING**，不可标记 CLOSED。

## 待处理的已知差距

- `evals.s25_01_live` 当前只评测 Understanding 子系统，不包含完整 Direct-vs-Structured Agent API 性能对照；该门禁仍需在有真实模型服务的环境补跑。
- `GoalSpec` 的复杂新增/目标取消/局部更正与 PlanLedger 对齐仍需专项 E2E 样例。结构化 GoalState 不能自动宣称旧计划步骤失效或外部副作用已回滚。
- 默认模式目前保留 Direct。转为 Structured 不应仅通过合并 PR 自动生效。

## 新增：单命令正式 API 真实运行（推荐优先）

无需同时启动两个 Uvicorn 服务。单命令对照工具在相同 Python 进程中，分别构造 Direct / Structured 的真实 FastAPI 应用及各自独立的临时 SQLite 数据库。每次请求使用现有正式 Conversation API，**不会使用模拟 Agent Decider**。

```powershell
$env:RUN_S25_01_LIVE="1"
$env:MODEL_PROVIDER="ollama_proxy"
$env:MODEL_BASE_URL="http://127.0.0.1:11434"
$env:MODEL_NAME="qwen3:14b"
$env:UNDERSTANDING_LIGHT_MODEL="qwen3:4b"
$env:UNDERSTANDING_STRONG_MODEL="qwen3:14b"
python -m evals.s25_01_local_e2e --output s25_01_e2e.json
```

特别注意：
- 在本机运行前用 `ollama list` 核查**实际**可用的模型标识；若使用代理，则按代理实际模型名及地址配置。
- 先运行独立 Understanding benchmark，再运行单命令 E2E，提交**脱敏** JSON 结果以进行错误分类和后续审查。
- API E2E 的顺序测试容易受模型缓存和换载影响，需至少测冷、热两轮并注明设备/显存，不能用这份小样本报告直接决定默认切换。
- 当前环境并不能访问用户 Windows 上的 Ollama，所以以上为**待用户机器执行的命令**，并非已完成的真实模型物理验证。
